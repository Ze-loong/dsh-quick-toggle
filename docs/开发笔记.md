# dsh-quick-toggle 开发笔记

> 写给以后开发 DeepSeek Harness（DSH）插件的自己：这个插件用到的 DSH 机制、踩过的坑和验证方法。
> 基于 DSH 0.2.2-rc.5（2026-11）。

## 1. 插件结构

一个 DSH 插件就是一个 npm 包，`package.json` 里的 `dsh` 字段声明两件事：

```jsonc
"dsh": {
  "bundle": { "patch": "./cordis.patch.yml" },     // 包启用时插入哪些插件条目
  "client": { "platform": "web", "inject": [...] }  // 浏览器端模块，exports["./client"] 指向它
}
```

| 文件 | 跑在哪 | 作用 |
|---|---|---|
| `index.js` | Host（Node） | Cordis 插件：`export const name / inject / Config`、`export function apply(ctx, config)` |
| `client.js` | 浏览器 | `window.__ModuleLoader__.load({ id, factory(require) {...} })`，`module.exports = { apply, inject }`；`require('react')` / `require('react-dom')` 由页面提供 |
| `cordis.patch.yml` | — | `- insert: [{ id: quick-toggle, name: 'dsh-quick-toggle' }]` |

用户的开关和配置写在 profile 的 `cordis.patch.yml`（用户补丁层）里，叠加在各插件包自带的补丁之上。

## 2. 用到的 DSH 接口

动手前用 `cordis_inspect_list` / `cordis_inspect_query` 查服务签名、插槽和主题变量，比猜靠谱得多。

| 需求 | 接口 |
|---|---|
| 列出/开关插件条目 | Host `ctx.pluginManager.listPlugins()` / `setPluginEnabled(entryId, enabled)`；浏览器 `ctx.get('remote.pluginManager')`，返回 `{ ok, value }` 信封 |
| 已安装但未启用的插件包 | `listBundles()` / `setBundleEnabled(name, enabled)`（未启用的包在 `listPlugins` 里**没有条目**） |
| 斜杠命令 | Host `ctx.commands.register({ name, description, input: { hint }, handler })`，返回 `{ kind: 'success' \| 'error', text }` |
| 只输入 `/命令` 时弹出列表 | 浏览器 `ctx.commandUi.decorate({ name, available, ui: { kind: 'popupSelect', options, onSelect } })`，与内置 `/permission` 同机制；选项支持 `group`、`badge`、`detail`、`confirmation`（官方确认页） |
| 选中后执行命令 | `ctx.sessions.binding(sessionId).session.command('/toggle …')`（只返回 `{ matched }`，结果文字出现在对话里） |
| 输入框工具栏按钮 | 插槽 `conversation.input.left` / `.right`（list 型，组件收到 `sessionId`）；浮层要 portal 到 `document.body` |
| 插件页里的配置面板 | 插槽 `plugins.bundle.config`，key 为包名，组件收到 `{ view: 'summary' \| 'page' }`。**DSH 0.2.x 不会为第三方插件自动生成配置表单** |
| 读/写自己的配置 | 浏览器 `remote.settings.describe()` / `update(ns, patch, revision)`；Host `ctx.get('settings')`。ns 是 patch id |
| 主题颜色 | CSS 变量 `--dsw-alias-*`（`bg-overlay`、`label-primary`、`brand-primary`、`state-error-primary` 等），自动适配深浅色 |

## 3. 踩坑清单

| # | 现象 | 原因 | 解决 |
|---|---|---|---|
| 1 | 列表里只有开着的插件 | “已安装但整包未启用”的包在运行时没有条目 | 额外读 `listBundles()`，未启用的包整包开启 |
| 2 | 关掉插件后它的按钮/图标还在 | 浏览器端模块按**插件包**加载，只关条目不卸载前端 | 关掉包里最后一个开着的条目时连包一起停用；个别插件不能热卸载，提供“刷新页面” |
| 3 | 写配置报 `has no volatile fields`；插件页没有配置表单 | 设置服务只允许在线修改标了 `.volatile()` 的字段 | Config 每个字段 `.volatile()`；运行时读到的是带 `get()` 的引用，读值要 `v.get()`；改动不会让插件重载 |
| 4 | 批量关闭一部分“失败”、恢复一部分“失败” | 连续改动时下一个请求可能被拒；整包刚启用时条目要晚一点才出现 | 每步“发出 → 轮询真实状态 → 没生效就重试（最多 6 次）”；被拒时短暂等待直接重试，不要干等状态变化 |
| 5 | 关掉某插件后官方智能体预设卡在 pending | 它提供了核心插件依赖的服务（例：billion-context 的 compaction 服务） | 检查 `ChangeResult.warnings` 里 `(@deepseek-ai/...): pending` 的行，出现就立即重新打开；默认加入确认名单 |
| 6 | 重新开启的插件 `fiberPhase: failed`，`command "xxx" is already registered` | 那个插件的旧实例卸载时没释放命令名 | 无法热修，报告“启动失败，重启 DSH” |
| 7 | 操作显示失败，其实已经生效 | 被关的插件热重载打断了请求的返回值 | 永远以重新读取的真实状态为准，不以返回值为准 |
| 8 | `window.confirm` 不可靠 | 桌面环境可能拦截原生对话框 | 用“点两次确认”或 popupSelect 的 `confirmation` |
| 9 | link 安装后裸 `import '@deepseek-ai/schemastery'` 解析不到 | link 包的真实路径不在 profile 下 | 先正常 import，失败再从 profile 目录 `createRequire`；声明为可选 peerDependency |
| 10 | 两个开关请求并发时状态乱 | 插件管理服务的改动是串行生效的 | Host 端命令串行执行；不要并发调用 `set_plugin` |
| 11 | 桌面端 Ctrl+R 不刷新 | 桌面壳没绑这个快捷键 | 插件内提供 `location.reload()` 按钮 |

## 4. 安全边界

- 列表排除：本插件自己、`cordis:*`、DSH 自带的 `@deepseek-ai/*`（`availability !== 'profile'`）、`readOnlyReason` 非空的条目。按“是否用户自装”判断，而不是只看名字前缀——用户也可能装名字以 `@deepseek-ai/` 开头的第三方包。
- LiveShare 下 `commands/execute` 是 owner-only，访客不能运行 `/toggle`。
- 所有改动都走官方 `pluginManager`，写用户补丁层，不碰插件文件；最坏情况可以手动编辑 `cordis.patch.yml` 恢复。

## 5. 验证方法

- `npm test`：用“有状态 + 刁难”的模拟插件管理服务跑 Host 端命令（补丁层记住 disabled、整包停用后条目消失、启用后条目延迟出现、40% 随机拒绝、核心依赖告警、启动失败），再用假的 ModuleLoader 加载浏览器端做冒烟测试。
- 模拟不能代替真机：每次改完要在真实 DSH 里点一遍，尤其是批量操作。第一次真机批量关闭就暴露了模拟没覆盖的“请求被拒”问题。
- 调试工具：`plugin_manager`（list / set，逐个串行调用）、`cordis_inspect_query` 的 `Slots` / `Config` 提供方看插槽占用和配置 schema；需要看官方实现时，可以把 `app.asar` 里的 `@deepseek-ai/*` 源码解出来读。

## 6. 新插件开工清单

1. 先查有没有现成服务和插槽（`cordis_inspect`），再决定方案。
2. 包名先查 npm 和 awesome-dsh-plugin 目录有没有重名；patch id、CSS 类名前缀、localStorage key 都带插件专属前缀。
3. 要让用户改的配置一律 `.volatile()`，并自己挂 `plugins.bundle.config` 面板。
4. 所有状态变更“发出 → 核对真实状态 → 重试”，结果给出真实原因。
5. 写模拟测试，再真机全流程跑一遍。
